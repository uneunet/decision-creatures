# ADR 0005: UI 構築に Tailwind CSS・Motion を主軸とし shadcn/ui を最小限に利用する

## Status

Superseded by [ADR 0008](./0008-headless-base-ui-and-flat-pop-design-system.md)

## Context

`decision-creatures` はクリーチャーのコレクションやバトルというゲーム性・視覚体験が価値の中心にあるアプリケーションであり、汎用 SaaS ダッシュボードのような既製 UI コンポーネントの見た目では世界観が損なわれる。また、不要なセカンダリラベルや説明を排し「レイアウトに説明させる」設計を実現するには、細部の余白・タイポグラフィ・動きを自由に制御できる必要がある。一方で、モーダルやダイアログ等のアクセシビリティ実装を一から自前実装するのはコストが高い。

## Decision

UI スタイリングとアニメーションの主軸として **Tailwind CSS** と **Motion** を採用し、独自スタイリングによるデザイン性を最優先とする。**shadcn/ui** はアクセシビリティやフォーカス制御が必要な汎用 UI プリミティブなど、必要な場面にのみ限定して導入する。

## Consequences

### Pros

- Tailwind CSS と Motion の組み合わせにより、カード演出・スキャン表現・遷移などの独自デザインと滑らかなインタラクションを高密度に実装できる。
- shadcn/ui を全面採用しないことで、既製デザインへの引きずられを防ぎ、レイアウト主導のミニマルな情報設計を貫ける。
- 必要な箇所のみ shadcn/ui（Radix ベース等）を借りることで、アクセシビリティやキーボード操作の品質を効率よく担保できる。

### Cons

- 独自コンポーネントの設計・実装割合が高まるため、デザインシステムやトークン（色・余白・モーション規則）をプロジェクト内で一貫して管理する規律が必要になる。
- 汎用 UI ライブラリに全面依存する場合と比べ、一部コンポーネントの初期構築コストが増える。
