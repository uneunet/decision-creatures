# ADR 0008: ヘッドレス UI 基盤に Base UI (`@base-ui/react`) を採用し、フラットポップなデザインシステムで統一する

## Status

Accepted

## Context

[ADR 0005](./0005-ui-styling-with-tailwind-motion-and-minimal-shadcn.md) では Tailwind CSS + Motion に加えて `shadcn/ui` を最小限に利用する方針としていた。しかし、クリーチャーカードのモック検証を通じて以下の課題と方向性が明確になった。

1. **既製スタイルからの脱却と統一感**: `shadcn/ui` はコピー＆ペースト前提の既製スタイルを持つため、独自のポップな質感・色面構成を持つアプリ全体でトーンを揃えるには、スタイルを持たないヘッドレスコンポーネント基盤（アクセシビリティ・キーボード操作・フォーカス管理・ポップアップ配置のみを担う層）の上に自前のデザインシステムを構築する方が一貫性と保守性が高い。
2. **無文脈・フラットポップなデザイン言語の確定**: ユーザーが撮影・投入する写真は日用品から風景・動物・抽象画まで多岐にわたる。SF やファンタジー等の強い世界観装飾や、ぼかしドロップシャドウ・グロー・グラデーション多用の質感は被写体と干渉しやすい。検証の結果、以下を核とする **S1（フラットポップ・キャンディリップ＋切手シール）** 路線を基準デザインとして確定した。
   - **フラット＋構造の厚み**: ぼかし影・グロー・グラデーション・ガラスぼかしを使わず、単色ベタ塗り・属性色の枠線・下端リップ（厚み）で立体感と押し心地を表現する。
   - **属性連動カラー**: 主タイプ（`substance` 7 種）ごとにカード背景・枠線・下端リップ・タイプバッジの色を切り替える。
   - **ステッカー質感のレア度表記**: ギザギザ切手ダイカットの丸シール上に頭文字（`C` / `U` / `R` / `E` / `M`）と色のみで表現する。
   - **3D 反転＋フラットゲージ**: カードタップで 3D 反転し、裏面に色分けされたフラットゲージと英語＋簡潔な日本語訳（`HP 体力` / `ATK 攻撃` / `DEF 防御` / `SPD 速さ` / `SP 特殊`）を表示する。
3. **React 19 / Tailwind CSS v4 / Motion との親和性**: React 19 ネイティブ対応・単一パッケージでツリーシェイク可能・`render` prop により `motion` 要素と自然に合成できるライブラリが望ましい。

## Decision

[ADR 0005](./0005-ui-styling-with-tailwind-motion-and-minimal-shadcn.md) を置き換え、UI コンポーネント基盤とデザイン方針を以下の通り決定する。

1. **ヘッドレス UI 基盤**: `shadcn/ui` は導入せず、**`@base-ui/react`（Base UI）** を採用する。メニュー（`Menu`）、ダイアログ（`Dialog`）、進捗（`Progress`）、メーター（`Meter`）、トグル群（`ToggleGroup`）、ボタン（`Button`）などのアクセシブルな振る舞いは Base UI に委譲する。
2. **スタイリングとモーション**: すべての見た目は **Tailwind CSS v4** と自前トークン（`src/ui/theme.ts`）で定義し、カード 3D 反転やゲージ遷移は **Motion（`motion/react`）** で実装する。
3. **統一デザインシステム（フラットポップ / S1 基準）**: ぼかしドロップシャドウ・グロー・グラデーションを排した単色フラット構成＋下端リップをカードだけでなくボタン・メニュー・ダイアログ等の全共通コンポーネントへ適用し、属性連動カラーと不要な説明を置かないレイアウト主導の UI を貫く。

## Consequences

### Pros

- Base UI がフォーカス制御・ARIA 属性・キーボード操作・ポップアップ位置計算を担うため、アクセシビリティを損なわずに S1 基準の独自フラットポップ外観を全コンポーネントへ一貫適用できる。
- `@base-ui/react` は単一パッケージで React 19 にネイティブ対応しており、`render` prop や `data-starting-style` / `data-ending-style` により Tailwind CSS v4・Motion との組み合わせが簡潔になる。
- 既製 UI コンポーネントのスタイル上書きが発生せず、属性カラーや下端リップといった独自トークンを `src/ui/` 配下で一元管理できる。

### Cons

- `shadcn/ui` のような既製レシピに頼らないため、利用するプリミティブ（`PopButton` / `PopMenu` / `PopDialog` / `PopStatMeter` 等）ごとに薄いラッパーを自前で整備・維持する必要がある。
- ぼかし影やグラデーションを使わない制約のもとで視認性と階層を保つため、色コントラスト・境界幅・余白設計の精度が求められる。
