# ADR 0010: v1 UI フローをコレクション起点（`/`）・クロップ付きスキャン（`/scan`）・表裏 PNG 共有＋ライト／ダーク対応で確定する

## Status

Accepted

## Context

[ADR 0008](./0008-headless-base-ui-and-flat-pop-design-system.md)（Base UI + S1 フラットポップデザインシステム）および [ADR 0009](./0009-client-routing-with-tanstack-router.md)（TanStack Router）の決定を受け、v1 (MVP) 全体の画面遷移・初回モデル読込・クロップ・共有・テーマ方針をインタラクティブモックで検証した結果、以下の要件が確定した。

1. **コレクション起点のルート構成**: 日常的に貯めたカードを見返す体験を主軸とし、`/` をコレクション一覧（0 件時のみ大きなスキャン枠を表示）、スキャン専用画面を `/scan`、個体詳細を `/creatures/$id` とする。
2. **クロップ前処理による構図と推論精度の両立**: スキャン前にカード写真枠内でドラッグ／ズーム調整を挟むことで、カードの見た目を整えつつ背景ノイズを除外した状態で `LiquidAI/d1-2B` へ入力できる。
3. **初回 1.68 GB ダウンロードの透明性**: 起動直後にブロッキングせず、初回スキャンかつ Cache API 未保存時のみ一言確認してカード枠内のプログレスバーでダウンロードする。
4. **自動保存とシームレスな一覧復帰**: 推論完了と同時に Dexie.js へ自動保存して 180° リビールし、その場の `コレクションへ` ボタンから 1 タップで `/` へ戻れる導線を設ける。
5. **クライアント完結の共有／画像保存**: サーバーを持たない v1 でも、表＋裏の 2 枚並び S1 カードを Canvas で 1 枚の PNG に書き出し、Web Share API およびダウンロードで共有可能にする。
6. **アイコンとテーマ統一**: 全アクションに `lucide-react` のアイコンを一貫適用し、ライト／ダーク切替をフラットポップ原則（ぼかし影・グロー・グラデーションなし）のまま両立させる。

## Decision

v1 の画面構成・インタラクション・アイコン／テーマ基盤を以下の通り決定する（ルート配置は [ADR 0009](./0009-client-routing-with-tanstack-router.md) の TanStack Router 基盤を継承しつつ `/`・`/scan`・`/creatures/$id` に整理する）。

1. **ルート構成**:
   - `/`: コレクション一覧（Search Params `type` / `rarity` / `sort` 同期、スマホ 2 列・PC 3〜4 列のコンパクト S1 カード、下部 `+ スキャン` ボタン、0 件時はスキャン枠を表示）
   - `/scan`: 画像入力（ファイル／D&D／貼り付け／カメラ）→ カード枠内ドラッグ／ズームクロップ → 未キャッシュ時のみ 1.68 GB 確認＆進捗表示 → 自動保存＋180° 反転リビール → `コレクションへ` ボタンで `/` へシームレス復帰
   - `/creatures/$id`: フルサイズ S1 反転カード＋下部アクションバー（表裏切替・共有・画像保存・11Q 詳細・`···` から名前変更 `Dialog` / 削除 `AlertDialog`・`コレクションへ`）
2. **アイコンライブラリ**: **`lucide-react`** を採用する。
3. **クライアント PNG 書き出し**: 表面＋裏面の 2 枚並びを 1 枚の PNG としてブラウザ内 Canvas で生成し、Web Share API（非対応環境はダウンロードフォールバック）および画像保存を提供する。
4. **ライト／ダークテーマ**: `useThemeStore`（`localStorage` 永続化＋OS 設定追従）により全画面でライト／ダーク切替に対応する。ヘッダーは全画面で `ロゴ`＋`≡` メニュー固定とする。

## Consequences

### Pros

- 初回起動時の離脱を抑えつつ、1.68 GB ダウンロード前にユーザー同意を取れる。
- クロップ済み画像を推論・保存の両方に使うため、被写体精度とカード構図が一致する。
- 表裏 2 枚並び PNG のクライアント生成により、サーバーなしでも v1 からそのまま共有体験を提供できる。
- `lucide-react` と Base UI＋フラットポップトークンの組み合わせにより、ボタン・メニュー・ダイアログ全体で視覚的一貫性を保てる。

### Cons

- `/scan` にクロップ工程が 1 ステップ増えるため、ドラッグ／ズーム操作の応答性と初期フィット（中央自動配置）の使いやすさを担保する必要がある。
- Canvas による PNG 描画は S1 カードの CSS 実装と見た目を揃えて維持するコストがある。
