# ADR 0003: ブラウザ内推論に LFM3-d1-2B と ONNX Runtime + Web Worker を採用する

## Status

Superseded by [ADR 0006](./0006-minimal-webgpu-inference-for-d1-2b-with-precompiled-prompts.md)

## Context

本アプリの中核は「ユーザーが与えた画像からタイプとステータスを判定すること」にある。サーバーサイド API で VLM を呼ぶ構成は API コストとレイテンシ、画像プライバシーの課題が生じる。また、ブラウザ上で自己回帰型の言語生成モデルを動かすと、JSON 出力のパース不安定さや推論時間の長さが UX を損ねやすい。さらに、重い推論処理をメインスレッドで実行すると UI 描画やアニメーションが停止する。

## Decision

画像からのタイプ・ステータス判定モデルとして **LFM3-d1-2B** を採用し、ブラウザ上で **ONNX Runtime** を使って実行する。推論処理およびモデル管理はすべて専用の **Web Worker** に分離して実行する。

## Consequences

### Pros

- `LFM3-d1-2B` は単一フォワードパスで分類・スコアリングを行えるため、生成揺れのない構造化されたタイプ・ステータス判定と相性が良い。
- v1 において外部推論 API コストなしで無制限にクリーチャー生成を提供できる。
- Web Worker へのオフロードにより、モデルロードや推論中もメインスレッドの UI 操作やアニメーションの応答性を維持できる。

### Cons

- 約 2B クラスのモデル重みを初回にブラウザへダウンロード・キャッシュする必要があり、ネットワーク帯域と端末メモリ/ストレージを消費する。
- WebGPU 非対応環境や低スペック端末では WASM フォールバックによる推論速度低下が起きるため、量子化モデルの選定やローディング UX の工夫が求められる。
- LFM3 の ONNX グラフはプレーンな ONNX Runtime ベースであるため、前処理・トークナイズ・後処理パイプラインを自前で整備する必要がある。
