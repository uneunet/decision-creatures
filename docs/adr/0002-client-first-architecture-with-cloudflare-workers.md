# ADR 0002: v1 はブラウザ完結とし、Cloudflare Workers を基盤に段階的拡張する

## Status

Accepted

## Context

v1 (MVP) では「画像からクリーチャーを生成してコレクションする」コア体験を最小の運用コストと短いリードタイムで立ち上げたい。一方、将来的にバトル機能を実装する段階では、対戦ロジックの整合性担保、データ永続化、画像アセット共有のためにサーバーサイド処理が不可欠になる。最初からフルスタック基盤を構築すると MVP の複雑性が増し、逆に静的ホスティング専用サービスを選ぶと後のサーバー追加時に基盤移行コストが発生する。

## Decision

ホスティング基盤として **Cloudflare Workers** を採用する。v1 (MVP) ではサーバーサイド処理を一切持たず静的アセット配信のみに利用し、バトル機能を実装するフェーズで Workers 上にサーバーロジックを実装するとともに、永続データに **Cloudflare D1**、画像等のオブジェクト保存に **Cloudflare R2** を追加する。

## Consequences

### Pros

- v1 ではサーバー運用や DB 管理、画像転送コストをゼロに抑えつつ、迅速に MVP をリリースできる。
- v1 でユーザーが入力した画像が外部サーバーへ送信されないため、プライバシー面で明確な安心感を提供できる。
- バトル実装時も同一の Cloudflare エコシステム（Workers + D1 + R2）上でシームレスに拡張でき、インフラの乗り換えが不要になる。

### Cons

- v1 のデータはブラウザローカルに閉じるため、端末間のデータ同期やオンライン対戦は v2 以降の実装となる。
- Cloudflare Workers ランタイム固有の制約（実行時間・メモリ・CPU 制限や D1 の SQLite 特性）を前提とした API 設計が必要になる。
